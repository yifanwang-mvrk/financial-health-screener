## 1. Frozen MVP Scope

This project is currently frozen as a CV-ready MVP.

The MVP does not expand back into the original v3.0 large framework. It focuses on proving one clean, explainable workflow:

1. Collect a small public-company financial statement dataset.
2. Validate that the raw financial data is complete and internally consistent.
3. Normalize the dataset into an analysis-ready structure.
4. Use SQL to calculate financial health indicators and risk signals.
5. Export a simple company-year risk ranking suitable for explanation in a CV, project portfolio, or Power BI dashboard.

Frozen company sample:

- AMZN
- EBAY
- ETSY
- CHWY
- DASH
- BKNG

Frozen period:

- Fiscal years 2021, 2022, and 2023
- Expected MVP coverage: 6 companies x 3 years = 18 company-year rows

Current business question:

Can basic financial deterioration signals identify publicly listed e-commerce or e-commerce-adjacent companies with higher financial risk before severe distress becomes obvious?

## 3. Core File Roles

### `README.md`

Business purpose:

Defines the project as a financial distress signal analysis pipeline for e-commerce companies, using SQL, pandas, and Power BI.

Technical role:

Acts as the public-facing project summary. It is currently short and still says the project is in progress.

### `docs/project_status.md`

Business purpose:

Records the original project direction and phase tracking. It still describes the project as being in A2 financial data collection.

Technical role:

Useful as historical status documentation, but it is behind the current MVP implementation because the pipeline and risk ranking now exist.

### `data/raw/financial_statements_raw.csv`

Business purpose:

Stores the source-level financial statement facts used to evaluate company health. It includes revenue, profitability, liquidity, leverage, cash flow, and source notes.

Technical role:

Input table for validation and pipeline processing. Values are in USD millions, with optional blanks where a metric is not reported or not meaningful for a business model.

### `src/check_financial_statements.py`

Business purpose:

Protects the credibility of the analysis by checking whether the financial dataset is complete, consistent, and aligned with the frozen MVP sample.

Python role:

Uses pandas to:

- Read raw financial statements and company master data.
- Check the expected column schema.
- Check required fields.
- Detect duplicate ticker-year rows.
- Confirm all frozen MVP ticker-year rows exist.
- Confirm tickers exist in the company master.
- Validate fiscal years, dates, and numeric columns.
- Check free cash flow equals operating cash flow minus capital expenditure.
- Check assets approximately equal liabilities plus equity.

### `src/build_mvp_pipeline.py`

Business purpose:

Turns raw collected data into repeatable analytical outputs. This is the main pipeline that makes the MVP reproducible.

Python role:

Uses pandas and DuckDB to:

- Read the raw CSV.
- Sort and convert numeric columns.
- Validate accounting relationships again before processing.
- Write the normalized CSV.
- Create or replace a DuckDB table called `financial_statements`.
- Run the MVP SQL file.
- Export `financial_metrics.csv` and `risk_ranking.csv`.
- Print the latest-year risk ranking.

### `sql/financial_health_screener_mvp.sql`

Business purpose:

Defines the financial logic of the screener: ratios, trend changes, risk signals, risk scores, tiers, and ranking.

SQL role:

Creates three analysis tables:

- `financial_metrics`: company-year ratios and year-over-year changes.
- `risk_signals`: boolean deterioration flags.
- `risk_ranking`: final score, risk tier, triggered signal text, and rank by fiscal year.

Current risk signals:

- Revenue decline
- Negative operating income
- Operating margin deterioration
- Negative free cash flow
- Free cash flow deterioration
- Current ratio below 1
- Negative equity
- Rising liabilities-to-assets

### `data/processed/risk_ranking.csv`

Business purpose:

Final MVP output for analysis, dashboarding, and CV demonstration.

Technical role:

CSV export from DuckDB containing one row per company-year with calculated ratios, signal score, tier, and rank.

## 4. How To Run

Run commands from the project root:

```bash
cd /Users/wangyifan/Desktop/Projects/financial-health-screener
```

Use the project virtual environment:

```bash
.venv/bin/python --version
```

Validate raw financial statements:

```bash
.venv/bin/python src/check_financial_statements.py
```

Business purpose:

Confirms the dataset is reliable enough to analyze.

Python action:

Reads raw CSV files with pandas and exits with an error if schema, coverage, numeric fields, duplicate rows, free cash flow, or balance-sheet relationships fail.

Build the MVP pipeline:

```bash
.venv/bin/python src/build_mvp_pipeline.py
```

Business purpose:

Produces the analysis-ready data and final risk ranking.

Python and SQL action:

Python loads and normalizes the raw data, writes it to DuckDB, executes the SQL analysis, and exports processed CSV outputs. SQL calculates ratios, flags deterioration signals, assigns risk tiers, and ranks companies within each fiscal year.
